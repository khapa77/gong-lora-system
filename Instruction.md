# Gong Server — полная инструкция (ветка `standalone-max`, FW 6.2-max)

Одиночный автоматический гонг для многодневного курса: одно устройство на
ESP32 с расписанием, веб-интерфейсом, усилителем MAX98357A на динамик,
часами DS3231. Реле, светодиода и кнопки в этой версии нет — всё управление
только через веб-интерфейс по Wi-Fi.
Интернет и роутер не нужны — устройство само поднимает точку доступа Wi-Fi. Если интернет есть, время
подтягивается по NTP.

## 1. Состав и подключение

| Компонент | Назначение |
|---|---|
| ESP32 DevKit (38 pin, ESP32-WROOM-32) | контроллер, Wi-Fi |
| MAX98357A (модуль, Adafruit #3006 или клон) | I2S-усилитель класса D, 3 Вт @ 4 Ом при 5 В |
| Динамик 4–8 Ом, от 3 Вт | на клеммник MAX98357A |
| DS3231 For Pi (мини-модуль под Raspberry Pi) | часы реального времени с батарейкой |
| HLK-10M05 (5 В, 2 А) | питание от сети 220 В |

### Распиновка

Схема с номерами пинов DevKit встроена в прошивку: **`http://gongN.local/info`** (или `http://192.168.4.1/info`),
ссылка «Схема» в шапке веб-интерфейса. Краткая инструкция для обслуживающего —
`http://gongN.local/guide` (ссылка «Инструкция», исходник [server/web/guide.html](server/web/guide.html)). Исходник — [server/web/info.html](server/web/info.html), открывается и локально в браузере.

| Сигнал | GPIO ESP32 | Куда | Примечание |
|---|---|---|---|
| I2S BCLK | 26 | MAX98357A BCLK | |
| I2S LRC (WS) | 25 | MAX98357A LRC | |
| I2S DATA | 33 | MAX98357A DIN | |
| 5 В | 5V | MAX98357A Vin | 3 Вт — только от 5 В |
| — | — | MAX98357A GAIN, SD | не подключать |
| I2C SDA | 21 | DS3231 SDA | питание DS3231 — 3.3 В |
| I2C SCL | 22 | DS3231 SCL | |

### Важно по железу

- **MAX98357A, SD:** не подключать. На breakout стоит резистор SD → Vin,
  он выбирает канал (у Adafruit при 5 В — (L+R)/2, у клонов бывает только
  левый). Прошивка всё равно сводит запись в моно (`audio.forceMono(true)`),
  поэтому звук полный при любом выборе канала.
- **MAX98357A, GAIN:** не подключён — 9 дБ. На GND — 12 дБ, на Vin — 6 дБ,
  через 100 кОм на GND — 15 дБ, через 100 кОм на Vin — 3 дБ.
- **Динамик:** выход мостовой — ни один провод динамика не соединять с GND
  и не подавать выход на вход другого усилителя.
- **DS3231 For Pi:** гнездо 5 контактов (как пины Raspberry Pi 1-3-5-7-9):
  3.3V, SDA, SCL, NC, GND — подключать по надписям, питание только 3.3 В.
  Подтяжек I2C на модуле обычно нет (у Pi они на самой плате): проверить
  мультиметром SDA→+ и SCL→+, при обрыве — 4.7 кОм от SDA и SCL к 3.3 В.
  Подробно — [docs/pinout.md](docs/pinout.md) §3.
- **Питание:** MAX98357A на громком ударе берёт до ~0.6 А — 5 В брать от
  блока питания, не через USB DevKit; 470–1000 мкФ у Vin модуля.
  Заземление звездой, 1000 мкФ у входа платы, 100 мкФ + 100 нФ у
  3.3 В ESP32. Подробно — `footprint/schematic_netlist.md`,
  `footprint/pcb_layout_notes.md`.

## 2. Установка ПО и сборка

Пошагово (PlatformIO, драйвер CP210x/CH340, права на порт) —
**[docs/platformio-setup.md](docs/platformio-setup.md)**. Коротко:

```bash
pip install -U platformio
git clone <репозиторий> && cd gong-lora-system
git checkout standalone
cd server
pio run                  # сборка (первый раз скачает тулчейн и библиотеки)
```

Что где лежит в `server/`:

| Путь | Что это |
|---|---|
| `src/` | прошивка |
| `web/index.html` | веб-интерфейс — **вшит в прошивку** при сборке |
| `data/` | файловая система LittleFS: `0001.mp3`, `0002.mp3`, `day00.conf` … `day11.conf`, `gong.conf` |
| `platformio.ini` | настройки сборки, пароль AP |
| `partitions_large_spiffs.csv` | разметка флеш-памяти (2.3 МБ под LittleFS) |

## 3. Прошивка: первая установка

Новая или стёртая плата:

```bash
cd server
pio run -t upload        # 1) прошивка (вместе с веб-интерфейсом)
pio run -t uploadfs      # 2) MP3 и расписания из data/ (несколько минут на 115200)
pio device monitor       # логи, выход Ctrl+C
```

Что лежит в `server/data/` и попадает на плату через `uploadfs`:

| Файл | Что это |
|---|---|
| `0001.mp3`, `0002.mp3` | звуки гонга (номер = поле «Track» в расписании) |
| `day00.conf` … `day11.conf` | расписание каждого дня курса |
| `gong.conf` | засев Дня 00 при самом первом запуске, дальше не используется |

Веб-интерфейса в `data/` нет — он внутри прошивки. Раздел LittleFS — 2,3 МБ,
занято ~1,1 МБ. Мусор вроде `.DS_Store` перед заливкой удаляется сам
(`scripts/clean_data.py`).

Если во время `Connecting.....` висит — зажать **BOOT** на плате до начала записи.

После загрузки в веб-интерфейсе красная плашка «Время не установлено» — это
нормально, время ещё не задано (см. §5).

## 4. Обновление с предыдущей версии

### С 6.0 / 6.1 на 6.2 — порядок важен

Перенос с прошивки `standalone` (6.2-solo, с реле) на `standalone-max`: достаточно
`pio run -t upload`. Настройки реле в NVS остаются, но не используются.

1. **Только `pio run -t upload`. Без `uploadfs`.**
2. Дать плате загрузиться один раз. При этой загрузке:
   - пароль админки, Wi-Fi и текущий день курса переносятся
     из файлов (`/auth.conf`, `/wifi.conf`, `/activeday.conf`)
     в NVS — в логе строки `Imported ... into NVS`;
   - время в DS3231 переводится из местного в UTC — в логе
     `Migrated DS3231 from local time to UTC`. Часы в веб-интерфейсе
     показывают то же время, что и раньше.
3. Проверить в веб-интерфейсе: пароль, Wi-Fi, активный день, время.

Если сначала сделать `uploadfs`, старые файлы настроек сотрутся раньше, чем
перенесутся, — всё придётся вводить заново.

### Дальнейшие обновления

| Что изменилось | Команда | Что потеряется |
|---|---|---|
| прошивка или веб-интерфейс | `pio run -t upload` | ничего |
| расписание (все дни) | веб: карточка **Course** → «Загрузить курс» | ничего, USB не нужен |
| MP3 в `data/` | `pio run -t uploadfs` | правки расписания из веба — заменятся на `data/dayNN.conf` |

Перед `uploadfs` сохраните курс: **Course → Скачать курс**, после заливки —
**Загрузить курс** этим же файлом. Пароль, Wi-Fi, номер устройства и текущий
день курса хранятся в NVS и `uploadfs` не затрагивает.

## 5. Первая настройка

1. С телефона подключиться к Wi-Fi **GongServer-XXXX** (у нового устройства
   XXXX — 4 символа из MAC; пароль по умолчанию `vipassana` — сменить, §10).
2. Открыть **http://192.168.4.1** (или **http://gongxxxx.local**).
3. **Device** — выбрать номер устройства из списка 1–9 (больше 9 — флагом `-DDEVICE_NUM` или через API, до 99) и подпись, например «Зал».
   Устройство перезагрузится с сетью **GongServer-N** и адресом
   **http://gongN.local** — подключиться к новой сети (пароль тот же) и
   продолжить. Номер и подпись видны в шапке страницы и во вкладке браузера.
   Подробно — §5a.
4. **Clock** — время. Один из вариантов:
   - вкладка **WiFi** → подключить к роутеру с интернетом → время придёт по
     NTP само (значок 🌐 NTP);
   - либо ввести дату и время вручную (UTC+3) → **Set Time**. Время
     запишется в DS3231 и переживёт выключение.
5. **Security** — задать пароль админки (≥ 8 символов). Логин — `admin`.
6. **Gong** — нажать **Play**: проверить звук.
7. **Schedule** — проверить активный день курса (при первом запуске — День 00)
   и расписание.
8. Красная плашка вверху страницы должна исчезнуть (кроме пунктов про пароли, если их не меняли).

### 5a. Несколько устройств

Чтобы гонги рядом не путались, у каждого свой номер (карточка **Device**):

| | Номер не задан | Номер N (1–99) |
|---|---|---|
| Wi-Fi сеть | `GongServer-A3F2` (из MAC) | `GongServer-N` |
| Адрес mDNS | `http://gonga3f2.local` | `http://gongN.local` |
| IP точки доступа | 192.168.4.1 | 192.168.4.1 |
| Шапка веба / вкладка | подпись, если задана | `#N · подпись` |

- Номер и подпись хранятся в NVS — переживают перепрошивку и `uploadfs`.
- Смена номера = перезагрузка через 2 с; подпись меняется сразу.
- Номера не должны повторяться: устройство не проверяет соседей.
- Партию можно прошить сразу с номером: `-DDEVICE_NUM=3` в `build_flags`
  (действует, пока номер не задан в вебе).
- Пароль Wi-Fi у всех одинаковый (`AP_PASSWORD` при сборке); пароль админки — у каждого свой.
- Пока номер не задан, в вебе предупреждение «Номер устройства не задан».

## 6. Ежедневная работа

### Дни курса

- 12 шаблонов: `day00` (заезд), `day01`–`day10` (основные), `day11` (отъезд).
- В полночь по календарной дате курс сам переходит на следующий день. Если
  устройство было выключено несколько суток — перейдёт сразу на нужное число
  дней вперёд. Перевод даты назад день не меняет.
- После `day11` устройство остаётся на `day11` и продолжает звонить по нему
  каждый день — это задумано: следующий курс запускают вручную.
- Кнопка **Activate this day** — сделать просматриваемый день активным
  (например, начать новый курс с Дня 00).

### Расписание

- Стрелками листать дни; редактировать можно любой день, не активируя его.
- Запись: время, трек, громкость 0–30, повторы 1–7, описание (до ~48 букв),
  вкл/выкл.
- Одна запись на минуту в пределах дня; до 32 записей в день.
- Трек должен существовать на устройстве (`/0001.mp3`, `/0002.mp3` …). Если
  файл трека пропал, в момент гонга сыграет трек 1.

### Курс одним файлом

Карточка **Course** — все дни курса сразу, вместо правки по одной записи:

- **Скачать курс** — файл `gong-course-<имя>.json`: резервная копия, заготовка
  для правки на компьютере, перенос на другие гонги.
- **Загрузить курс** — выбрать файл. Браузер проверяет его по тем же правилам,
  что и при ручной правке (время, трек есть на устройстве, громкость, повторы,
  одна запись на минуту, до 32 в день) и показывает сводку по дням. После
  «Залить на устройство» дни отправляются по одному, затем применяются разом.
- Текущий день курса и его дата **не меняются** — меняются только гонги. Новое
  расписание активного дня действует сразу.
- Если связь оборвалась посередине, старый курс остаётся целым (дни сначала
  пишутся в `/dayNN.new`, заменяют `dayNN.conf` только все вместе).

Формат: одинаковые дни описываются один раз в `templates`, `days` — имя шаблона
на каждый день (ровно `DAY_COUNT` = 12). Вместо имени можно вписать день целиком
списком. `id` не нужен, `track` по умолчанию 1, `loop` 1, `en` true, `vol` — громкость по умолчанию.

```json
{
  "format": "gong-course",
  "version": 1,
  "name": "10-дневный курс",
  "templates": {
    "first": [ {"hour":4,"min":0,"track":1,"loop":1,"en":true,"desc":"Подъём"} ],
    "main":  [ {"hour":4,"min":0,"track":1,"loop":3,"vol":20,"en":true,"desc":"Подъём"} ]
  },
  "days": ["first","main","main","main","main","main","main","main","main","main","main","first"]
}
```

Полный пример (то же, что в `server/data/`) — [docs/course-example.json](docs/course-example.json).
Экспорт сам сворачивает одинаковые дни в шаблоны `day00`, `day01`, … — их можно переименовать.

### Если питание пропало

- Гонг, время которого пришлось на перезагрузку, прозвучит сразу после
  включения, если прошло не больше 2 минут. Уже прозвучавший гонг не
  повторяется.
- Время идёт по DS3231, день курса и все настройки сохраняются.

## 7. Время

Источник выбирается автоматически, переключателя нет:

| Приоритет | Источник | Когда |
|---|---|---|
| 1 | 🌐 **NTP** | устройство подключено к Wi-Fi с интернетом. Опрос раз в час, каждый ответ сразу записывается в DS3231 |
| 2 | 🔋 **DS3231** | при загрузке; и раз в час, если NTP не отвечал больше 2 ч. Заодно убирает уход часов ESP32 |
| 3 | ✏️ **Вручную** | нет ни интернета, ни DS3231 с верным временем. Записывается в DS3231; при появлении интернета NTP перезапишет |

- Часовой пояс — `TIME_TZ` в `config.h`, по умолчанию `MSK-3` (UTC+3, без
  летнего времени).
- DS3231 хранит UTC.
- Без действующего времени гонги **не звучат** — красная плашка и
  значок ⚠️ Not set.
- Показания DS3231 с явным мусором (сбой шины I2C) отбрасываются.

## 8. Сброс пароля админки

Кнопки нет, поэтому забытый пароль сбрасывается по USB:

1. Подключить ESP32 к компьютеру кабелем USB.
2. `pio device monitor` (115200) или любой монитор порта.
3. Ввести `reset-auth` и нажать Enter.
4. В логе — `[AUTH] Admin password RESET by serial command`, вход в веб снова
   открыт, вверху плашка «Пароль админки не задан». Задать новый пароль.

Остальные настройки, расписание и время не меняются. **Не** стирать для этого
NVS целиком (`pio run -t erase` или `erase_region`): пропадёт и отметка
миграции DS3231, и при следующей загрузке время сдвинется на 3 часа.

Команда — `AUTH_RESET_CMD` в `config.h`. Неизвестная команда только пишется в лог.

## 9. Предупреждения

Светодиода в этой версии нет — всё, что мешает гонгу, видно только в
веб-интерфейсе и в `/api/status`.

### Красная плашка в веб-интерфейсе

| Сообщение | Что делать |
|---|---|
| ❌ Файловая система не смонтирована | `pio run -t uploadfs` |
| ❌ Файл активного дня не читается | активировать день заново; если не помогает — `uploadfs` |
| ❌ Время не установлено | Wi-Fi с интернетом, батарейка DS3231 или ручная установка |
| ⚠️ Последний перезапуск: … | плата перезагружалась из-за сбоя (питание, зависание) — см. §13 |
| ⚠️ Пароль точки доступа стандартный | задать свой `AP_PASSWORD` (§15) |
| ⚠️ Пароль админки не задан | вкладка Security |

## 10. Безопасность

- **Пароль точки доступа** (WPA2) — по умолчанию `vipassana`, задаётся при
  сборке (§15), минимум 8 символов.
- **Пароль админки** — по умолчанию выключен. Пока он не задан, любой
  подключившийся к AP может управлять гонгом и даже задать свой пароль —
  задайте его при первой настройке. Минимум 8 символов, хранится как
  PBKDF2-SHA256 с солью.
- Забыли пароль — команда `reset-auth` в Serial по USB (§8).
- Защита от подделки запросов: изменяющие запросы требуют заголовок
  `X-Gong-Request: 1`; принимаются только имена `192.168.4.1`, IP в сети
  роутера, имя устройства `gongN`, `gongN.local` (и `gongN.<слово>`).
- Неверный пароль проверяется не чаще раза в 3 с.
- Пароль Wi-Fi роутера хранится в NVS открытым текстом и наружу не отдаётся.

## 11. Где что хранится

| Данные | Где | `uploadfs` стирает? |
|---|---|---|
| Веб-интерфейс | прошивка | нет (обновляется `upload`) |
| MP3 (`/0001.mp3` …) | LittleFS | заменяет из `data/` |
| Шаблоны дней (`/day00.conf` … `/day11.conf`) | LittleFS | **да** — правки из веба пропадут (сохранить: Course → Скачать курс) |
| `/dayNN.new` (черновик загрузки курса) | LittleFS | удаляется при включении |
| `/gong.conf` | LittleFS | заменяет; используется только при самом первом запуске |
| Пароль админки | NVS `auth` | нет |
| Wi-Fi роутера | NVS `wifi` | нет |
| Активный день + дата, последний гонг | NVS `gong` | нет |
| Номер и подпись устройства | NVS `device` | нет |
| Отметка миграции DS3231 | NVS `gongtime` | нет |
| Счётчик сбоев | NVS `sys` | нет |
| Время | DS3231 (UTC) | нет |

Полное стирание всего: `pio run -t erase`, затем §3.

Формат `dayNN.conf` — JSON-массив:

```json
[{"id":1,"hour":4,"min":0,"track":1,"loop":3,"vol":20,"en":true,"desc":"Подъём"}]
```

## 12. Обслуживание

| Что | Как часто |
|---|---|
| Открыть веб-интерфейс: нет красной плашки, время верное | каждый день |
| Проверить время в веб-интерфейсе | перед курсом |
| Батарейка DS3231 | раз в год или при ⚠️ Not set после выключения |
| Перед курсом: активировать День 00, проверить расписание | перед каждым курсом |
| Сделать копию изменённых расписаний (скопировать `dayNN.conf` из веба в `data/`) | перед `uploadfs` |

## 13. Неисправности

| Симптом | Причина / решение |
|---|---|
| Красная плашка в веб-интерфейсе | она называет причину (§9) |
| Время ⚠️ Not set после выключения | села батарейка DS3231 или модуль не подключён (SDA 21 / SCL 22) |
| Время сдвинуто на 3 часа после обновления | обновлялись через `uploadfs` до первой загрузки или сменился `TIME_TZ`; установить время заново |
| Гонг не звучит | проверить `0001.mp3` в `data/`, громкость записи, динамик на клеммнике MAX98357A, питание Vin, провода BCLK/LRC/DIN |
| Звук тихий или хрипит | Vin 3.3 В вместо 5 В; динамик меньше 4 Ом; поменять усиление выводом GAIN (§1) |
| Плата перезагружается в момент гонга (`brownout`) | просадка 5 В на громком ударе — блок от 2 А, 470–1000 мкФ у Vin MAX98357A и у ESP32 |
| Веб не открывается по `gongN.local` | открыть по IP; на Windows без Bonjour mDNS может не работать |
| `Forbidden host` | открывать по IP или `gongN.local` этого устройства, не по чужому имени |
| Не открывается веб, AP есть | `pio device monitor` — смотреть лог загрузки |
| «Файловая система не смонтирована» | `pio run -t uploadfs` |
| Не прошивается `Timed out waiting for packet header` | зажать BOOT во время `Connecting…` |
| Забыли пароль админки | USB → монитор порта → `reset-auth` (§8) |

Подробный лог: `pio device monitor` (115200) или `GET /api/logs`.

## 14. API

Все пути — на `http://192.168.4.1`. «Пароль» — Basic auth `admin:пароль`,
если он включён. «Запись» — ещё и заголовок `X-Gong-Request: 1`.

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| GET | `/` | пароль | веб-интерфейс |
| GET | `/api/state` | пароль | всё сразу: status, schedule, days, device, wifi, auth |
| GET | `/api/status` | пароль | время, источник, день, `fs_ok`, `sched_error`, `reset_reason`, `crash_count`, `ap_default_pw`, `ntp_age`, `heap`, `fw`, `device_num`, `device_name` |
| GET | `/api/logs?n=40` | пароль | последние строки лога (до 64) |
| POST | `/api/time` | запись | `{"hour","min","year","month","day"}` — ручная установка |
| GET | `/api/schedule` | пароль | расписание активного дня |
| GET | `/api/days` | пароль | `{"active","count","ended"}` |
| GET | `/api/day?n=N` | пароль | шаблон дня N |
| POST | `/api/day/activate?n=N` | запись | сделать день N активным |
| POST | `/api/day/entry?day=N` | запись | добавить запись: `{"hour","min","track","loop","vol","desc"}` (`hour`, `min` обязательны) |
| PUT | `/api/day/entry?day=N&id=I` | запись | изменить запись (+ `"en"`) |
| DELETE | `/api/day/entry?day=N&id=I` | запись | удалить запись |
| GET | `/api/course` | пароль | все дни: `{"days":[[…],…]}` |
| PUT | `/api/course/day` | запись | `{"day":N,"entries":[…]}` — день в черновик `/dayNN.new`; день 0 начинает новую загрузку |
| POST | `/api/course/commit` | запись | заменить все дни черновиками (нужны все `DAY_COUNT`) |
| GET | `/api/tracks` | пароль | номера треков на устройстве |
| POST | `/api/play` | запись | `{"track","vol","loop"}` — гонг (loop ≤ 7) |
| POST | `/api/stop` | запись | стоп |
| GET | `/api/device` | пароль | `{"num","name","ssid","host","restarting"}` |
| POST | `/api/device` | запись | `{"num":0–99,"name":"…"}` — номер (0 = из MAC) и подпись ≤ 32 байт; смена номера — перезагрузка |
| GET | `/api/wifi` | пароль | статус подключения к роутеру |
| POST | `/api/wifi` | запись | `{"ssid","pass"}` — сохранить и подключиться |
| POST | `/api/wifi/forget` | запись | забыть сеть |
| POST / GET | `/api/wifi/scan` | запись / пароль | запустить скан / результат |
| GET | `/api/auth/status` | открыт | включён ли пароль |
| POST | `/api/auth/save` | запись | `{"password"}` — задать пароль (8–64) |
| POST | `/api/auth/disable` | запись | выключить пароль |

Пример:

```bash
curl -u admin:пароль -H "X-Gong-Request: 1" -H "Content-Type: application/json" \
     -d '{"track":1,"vol":20,"loop":1}' http://192.168.4.1/api/play
```

## 15. Константы и настройки сборки

### `server/platformio.ini` → `build_flags`

| Флаг | Что делает |
|---|---|
| `-DAP_PASSWORD='"${sysenv.GONG_AP_PASSWORD}"'` | свой пароль AP (сначала `export GONG_AP_PASSWORD='...'`, ≥ 8 символов) |
| `-DDEVICE_NUM=3` | номер устройства по умолчанию, пока он не задан в вебе (0 — из MAC) |
| `-DVOLUME_LIMIT=30` | без ограничения громкости — для HLK-10M05 (по умолчанию 25 под HLK-PM01) |
| `-DTIME_TZ='"<+05>-5"'` | другой часовой пояс (POSIX TZ) |

### `server/src/config.h`

| Константа | Значение | Смысл |
|---|---|---|
| `TIME_TZ` | `MSK-3` | часовой пояс |
| `NTP_SYNC_INTERVAL_MS` | 1 ч | опрос NTP |
| `NTP_STALE_MS` | 2 ч | дольше без NTP — «интернета нет» |
| `RTC_RELOAD_MS` | 1 ч | подтяжка времени из DS3231 |
| `MAX_SCHEDULES` | 32 | записей в день |
| `DAY_COUNT` | 12 | дней курса |
| `LOOP_MAX` | 7 | повторов |
| `DESC_MAX_BYTES` | 96 | описание (≈48 кириллических букв) |
| `CATCHUP_WINDOW_S` | 120 с | окно догоняющего гонга |
| `AUTH_RESET_CMD` | `reset-auth` | команда сброса пароля в Serial |
| `AUTH_MIN_PASSWORD` | 8 | пароль админки |
| `DEFAULT_VOLUME` | 30 | громкость по умолчанию (0–30) |
| `VOLUME_LIMIT` | 25 | потолок: громкость 30 звучит как 25 (−3.5 дБ), шкала масштабируется; 30 — без ограничения ([docs/power.md](docs/power.md)) |

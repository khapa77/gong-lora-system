# LoRa Signal Research — Gong System

История экспериментов с параметрами сигнала и аппаратными улучшениями.

---

## Хронология конфигураций

### Этап 1 — Начальная конфигурация (SF7)
**Коммит:** `7bcd64c` (GPIO_2-4) → `b6c5faa`

| Параметр | Значение |
|---|---|
| SF | 7 |
| BW | 125 kHz |
| CR | 4/5 |
| TX Power | 20 dBm |

Стандартные параметры LoRa по умолчанию. Быстро, но низкая чувствительность.  
**Time on Air** (50 байт): ~36 мс.

---

### Этап 2 — Увеличение дальности (SF10)
**Коммит:** `b0c2b74` — *"config: increase LoRa range — SF10, BW 62.5 kHz, CR 8; move DIO0 to GPIO4"*

| Параметр | Значение |
|---|---|
| SF | 10 |
| BW | 62.5 kHz |
| CR | 4/8 |
| TX Power | 20 dBm |

Также перенесён DIO0 с GPIO2 на GPIO4 (GPIO2 мешал прошивке).  
**Time on Air** (50 байт): ~560 мс.  
Чувствительность лучше на ~14 dB по сравнению с SF7.

---

### Этап 3 — Максимальная чувствительность (SF12)
**Коммит:** `a66d8c7` — *"config: maximize LoRa sensitivity for bad antennas — SF12, BW 31.25 kHz"*

| Параметр | Значение |
|---|---|
| SF | 12 |
| BW | 31.25 kHz |
| CR | 4/8 |
| TX Power | 20 dBm |

Причина: плохие антенны, нужна максимальная чувствительность.  
**Time on Air** (50 байт): ~8–17 сек (!).  
Чувствительность: до −148 dBm (лучшая у SX1278).  
**Проблема:** очень длинный TX блокировал аудио-воспроизведение на Core 1.  
Это стало причиной рефакторинга — перенос LoRa на Core 0.

---

### Этап 4 — Откат для тестирования (SF7, TX 6 dBm)
**Коммит:** `04262e4` — *"configs"*

| Параметр | Значение |
|---|---|
| SF | 7 |
| BW | 125 kHz |
| CR | 4/8 |
| TX Power | **6 dBm** |

Пониженная мощность (6 dBm вместо 20) и SF7 — вероятно для локального тестирования на короткой дистанции.  
**Текущий рабочий конфиг.**

## Аппаратные улучшения — открытые вопросы

### ⚡ Конденсатор на питание Ra-01 / Ra-02

**Наблюдение:** при работе с плохими антеннами и на граничных условиях приёма возможна нестабильность модуля из-за просадок питания во время TX-импульсов.

**Рекомендация к проверке:**  
Установить bypass-конденсатор **110–480 пФ** (до 5V) между `3.3V` и `GND` на ножках питания модуля Ra-01/Ra-02, максимально близко к самому модулю.

```
Ra-01
┌─────────┐
│ VCC ────┼──── 3.3V
│         │        │
│ GND ────┼──── GND
└─────────┘        │
               C (110–480 пФ)
               (к GND)
```

**Зачем:** конденсатор в диапазоне 100–500 пФ — это RF-bypass. Он фильтрует высокочастотные помехи на линии питания на частотах, близких к рабочей (433 MHz). Импульс тока во время TX (~120 мА) создаёт высокочастотный шум на шине питания, который может попасть обратно в RF-цепь и снизить чувствительность приёмника.

**Что проверить:**
- [ ] Измерить RSSI до и после установки конденсатора при одних и тех же условиях
- [ ] Проверить стабильность инициализации модуля при холодном старте
- [ ] Сравнить количество потерянных пакетов (heartbeat ACK miss) с конденсатором и без
- [ ] Подобрать оптимальную ёмкость в диапазоне 110–480 пФ под конкретную разводку PCB

**Дополнительно:** параллельно к RF-bypass рекомендуется bulk-конденсатор 10–100 мкФ на той же шине питания для компенсации импульсного потребления.

## Архитектурные изменения LoRa

| Версия | Подход | Проблема |
|---|---|---|
| v1 | `digitalRead(DIO0)` в `loop()` | Поллинг блокировал аудио при SF12 |
| v2 | `attachInterrupt` + `volatile bool` | Прерывание, но всё ещё Core 1 |
| **v3** | **Core 0 task + interrupt + FreeRTOS queue** | **Текущая версия — полная изоляция** |

**Коммит v3:** `40ea02d` — *"refactor: move LoRa to Core 0, replace DIO0 polling with interrupt"*

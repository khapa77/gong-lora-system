# Реле внешнего усилителя (ветка `standalone-max-button`)

Документ описывает восстановленное управление реле: назначение, аппаратные
требования, полный жизненный цикл, интеграцию с аудио и планировщиком, веб-API,
тестовую матрицу и риски. Кнопка, LED и сброс пароля — `docs/BUTTON_LED.md`.

## 1. Назначение и границы

Реле коммутирует нагрузку **вне платы** (разъём J3 → внешний модуль реле 5 В с
оптроном; контакты выведены на клеммы модуля). По схеме и документации донора это
питание внешнего усилителя / трансляционной линии.

MAX98357A питается независимо (`+5V_AUDIO` через FB1) и **не** управляется
реле. Следствия, принятые как контракт:

- `Always OFF` выключает только реле; встроенный гонг продолжает звучать;
- `Warm-up` нужен внешнему усилителю, а не MAX98357A;
- «реле включено без звука» (ручной режим) имеет смысл только для внешней
  нагрузки.

Физическая коммутируемая нагрузка (усилитель / линия / сеть) остаётся
неподтверждённой: это аппаратный вопрос, а не программный.

## 2. Аппаратная конфигурация

| Параметр | Значение |
|---|---|
| Пин | `RELAY_PIN` = **-1 по умолчанию** (функция выключена); кандидат по схеме — GPIO27 |
| Выход | `OUTPUT`, активный уровень `RELAY_ACTIVE_LOW` (0 = HIGH, 1 = LOW) |
| Обвязка | R10 100 Ом; R11 10 кОм → GND (active HIGH, запаян) / R12 → +3V3 (active LOW, DNP) |
| Разъём | J3: 1 = +5V, 2 = GND, 3 = RELAY_OUT |
| Безопасное состояние | неактивный уровень записывается **до** `pinMode(OUTPUT)` |

Номера выводов: GPIO27 существует и на классическом ESP32 (0–39), и на
ESP32-S3 (0–21, 26–48). На S3 **нет** GPIO22–25, а GPIO26–32 могут быть заняты
octal PSRAM/Flash конкретного модуля — проверяется по плате.

Блокер ветки не снят: `server/platformio.ini` собирает `esp32-s3-devkitc-1`,
физическая плата — ESP32-D0WD-V3. До подтверждения платы и полярности модуля
`RELAY_PIN` остаётся `-1`, включение — только `-DRELAY_PIN=27`
(+-`-DRELAY_ACTIVE_LOW=1`) после отдельного решения.

## 3. Жизненный цикл

Состояния не взаимоисключающие: одновременно могут быть активны ручной режим,
предвключение, воспроизведение и удержание. Модуль сводит их к одному выходу
«реле включено, пока есть причина»; наружу отдаётся производное `state` только
для индикации.

| Состояние (`state`) | Реле | Причина |
|---|---|---|
| `forced_on` | ON | режим Always ON из веба |
| `forced_off` | OFF | режим Always OFF из веба |
| `manual` | ON | ручное включение кнопкой, ≤ 30 мин |
| `warmup` | ON | старт отложен до истечения `pre` от включения реле |
| `prewarm` | ON | предвключение к гонгу расписания |
| `playing` | ON | звук идёт (`mp3_isPlaying()`) |
| `hold` | ON | звук закончился, ждём `holdMs` |
| `idle` | OFF | нет причин держать |
| `disabled` | — | `RELAY_PIN = -1` |

Правила:

1. `relay_play()` в AUTO сразу включает реле; звук стартует, когда от включения
   прошло `preMs` (или сразу, если реле уже прогрето). Повторный запрос во время
   ожидания заменяет параметры, но не сдвигает момент старта.
2. `relay_stop()` отменяет `pending` (отменённый гонг не стартует после
   прогрева), останавливает звук и отпускает реле через `holdMs`.
3. `relay_prewarm(msUntilGong)` включает реле заранее и держит до времени гонга
   + 5 с запаса (если гонг не пришёл — отпустит после удержания).
4. Ручной режим: только в AUTO, не пишется в NVS, живёт 30 минут.
5. `relay_setMode()` при выходе из AUTO во время `pending` запускает звук сразу —
   смена режима не теряет гонг.
6. `Always ON` **не восстанавливается** после перезагрузки: при старте
   сохранённый `ON` переводится в `AUTO`, реле выключено.
7. `mp3_isPlaying()` опрашивается не чаще `RELAY_POLL_PERIOD_MS` (50 мс), потому
   что берёт `audioMtx`, которую декодер держит на время `audio.loop()`.

Тайминги (`config.h`): `pre` 800 мс (0–30000), `hold` 3000 мс (0–20000),
`prewarm grace` 5000 мс, ручной режим 30 мин. Значения из NVS клампятся к
пределам при загрузке. Настройки — NVS-неймспейс `relay`, ключи `mode`, `pre`,
`hold`; одноразовый импорт `/relay.conf` из 6.1.

## 4. Интеграция

Единая точка запуска звука: **все** источники проходят `relay_play()` →
`mp3_start()`.

| Источник | Путь |
|---|---|
| Веб «Play» | `/api/play` → `mp3_manualPlay()` → `relay_play()` |
| Кнопка (3–8 с) | `ButtonHooks.playManual` → `mp3_manualPlay()` → `relay_play()` |
| Расписание (курс/легаси) | `onScheduleTrigger` → `relay_play()` |
| Аварийное расписание | `emergency::tick()` → `onScheduleTrigger` → `relay_play()` |

Остановка: `/api/stop`, кнопка (STOP) и «стоп всё» в планировщике
(`courseActivate`, `sched_courseApply`) вызывают `relay_stop()`, поэтому
отменённый `pending` не может стартовать позже.

Предвключение: раз в секунду после `sched_check()` `main.cpp` вызывает
`sched_msToNext()` и, если до события ≤ `preMs + 1000`, — `relay_prewarm()`.
`sched_msToNext()` пересчитывается из живых `entries[]` и живых часов, поэтому
сам учитывает: переход дня курса, правку/отмену события, Apply/Activate,
часовой пояс и коррекцию времени, а также возвращает −1 в состоянии
`APPLIED`/`waiting`, при ошибке расписания и в emergency.

Порядок вызовов в `controlTask` (под `sys_lock`): `button_loop` →
`sched_check` (1 Гц) → prewarm → `relay_loop` → `led_loop`. Порядок блокировок:
`sys_lock → audioMtx / logMtx`; собственных блокировок модуль не заводит.

`RELAY_PIN = -1`: `relay_play` вызывает `mp3_start` синхронно (без задержки и
без таймеров), `relay_loop` — no-op, `relay_isBusy()` == `mp3_isPlaying()`,
веб получает `enabled:false` и отвечает 400 на попытку настройки.

## 5. Кнопка и LED

| Условие | Удержание | Действие | LED |
|---|---|---|---|
| простой | < 3000 мс | игнорируется | heartbeat |
| простой | 3000…7999 мс | ручной гонг | ровный свет (`ButtonReady`) |
| простой | ≥ 8000 мс | реле вкл/выкл без звука | мигание 2 Гц (`RelayReady`) |
| звук/прогрев (busy) | ≥ 1000 мс | STOP (отменяет pending) | heartbeat |
| залип | ≥ 60000 мс | нажатие отменяется | heartbeat |

Приоритеты LED: AUTH_RESET (ровно, при загрузке) → BUTTON_READY (ровно) →
RELAY_READY (2 Гц) → ERROR (5 Гц) → NORMAL (60 мс/3 с).

## 6. Веб-API

`GET /api/relay` →

```json
{"enabled":true,"state":"warmup","mode":"auto","on":true,"pending":true,
 "prewarm":false,"manual":false,"hold":3000,"pre":800,"pin":27,
 "active_low":false}
```

`POST /api/relay`:

- `{"mode":"auto|on|off"}` — смена режима (сбрасывает ручной режим);
- `{"pre":0..30000,"hold":0..20000}` — тайминги (сохраняются в NVS);
- при `RELAY_PIN = -1` → 400 `relay not fitted (RELAY_PIN = -1)`.

`/api/status` содержит тот же объект в поле `relay`. UI: карточка
«Gong & Relay» — бейдж состояния, кнопки Auto / Always ON / Always OFF, поля
Warm-up и Hold after, обратный отсчёт ручного режима.

## 7. Тестовая матрица (host)

`python3 -B tests/run_relay_tests.py --build-dir /tmp/gong-relay-tests` — два
бинаря: `RELAY_PIN=27` (103 проверки) и `RELAY_PIN=-1` (17 проверок).

| Группа | Сценарии |
|---|---|
| Загрузка | значения по умолчанию; безопасный уровень до `pinMode`; сохранённый `ON` не восстанавливается; клампы таймингов; импорт `/relay.conf` |
| Запуск | холодное реле ждёт `pre`; прогретое — сразу; повторный запрос заменяет параметры, но не сдвигает старт |
| Остановка | стоп отменяет pending (гонг не стартует); стоп во время воспроизведения; реле отпускает через `hold` |
| Предвключение | держит до гонка + grace; гонг во время prewarm стартует без задержки |
| Ручной режим | включение/выключение, отказ вне AUTO, автоотключение 30 мин |
| Режимы | смена режима во время прогрева не теряет звук; Always OFF не останавливает звук |
| Ошибки | нет файла/декодер не стартовал — реле всё равно отпускает через `hold` |
| Границы | переполнение `millis()` в прогреве и удержании; busy-семантика; JSON |
| Без реле | `RELAY_PIN=-1`: звук без задержки, нет GPIO-операций, API отказывает |

Кнопка: 532 проверки (`run_button_tests.py`), включая 7999/8000/8001, STOP при
прогреве, игнорирование переключения вне AUTO, LED 2 Гц.
Планировщик: 270 проверок, включая `sched_msToNext()` (нет курса, APPLIED,
активированный день, после срабатывания, отключённое событие, emergency).

## 8. Риски

1. **BLOCKED**: плата не подтверждена (S3 vs ESP32-D0WD-V3); полярность модуля
   реле не подтверждена. До этого реле выключено, включённый код проверен только
   компиляцией.
2. Коммутируемая нагрузка неизвестна; при сетевом напряжении любые испытания —
   только по процедуре владельца.
3. `Warm-up` относится к внешнему усилителю; встроенный гонг от реле не зависит
   (документированный контракт, не дефект).
4. `mp3_isPlaying()` под `sys_lock` в `relay_loop` ограничен 20 Гц; фактическая
   задержка под нагрузкой не измерялась.
5. Flash занят ~88 %: реле + UI добавили ≈4 КБ в выключенной сборке и ≈15 КБ в
   включённой (compile-check).
6. Emergency идёт через тот же хук, но предвключения не получает (события
   аварийного расписания фиксированы); гонг просто ждёт прогрева.

## 9. Закрытие замечаний второго независимого ревью (c2788d5)

| № | Замечание | Статус | Как исправлено |
|---|---|---|---|
| 1 | Apply не атомарен относительно `controlTask` | FIXED | `sched_courseApply()` выполняет `relay_stop()` + `courseReloadCalendar()` + публикацию RAM под одним `sys_lock`; между стопом и `courseRunning=false` `sched_check()` больше не выполняется |
| 2 | Кнопка подменяет ожидающий гонг / переключает реле во время звука | FIXED | перед жестами простоя повторная проверка `hooks.busy()` (`pending || audio`); «стал занят за время удержания» → игнор, STOP по сырому фронту не затронут |
| 3 | Событие отмечалось прозвучавшим до старта аудио | FIXED | `onScheduleTrigger` возвращает `bool`; `doFire()` при отложенном старте не пишет watermark, `resolveDeferredFire()` фиксирует его по `relay_startCount()` и НЕ фиксирует при отмене (`relay_isPendingStart()==false`) |
| 4 | Ошибки записи NVS теряли `/relay.conf` и маскировались | FIXED | `saveConfig()` возвращает результат, `put*` проверяются; частичная запись (`mode` без `pre/hold`) считается отсутствующей; legacy-файл удаляется только после подтверждённой записи; сеттеры возвращают `false` |
| 5 | Ручной режим скрывал аудио от hold | FIXED | наблюдение за звуком и обновление `lastActiveMs` вынесены до ветки manual |
| 6 | prewarm и реальное расписание | FIXED / документировано | цель пересчитывается каждую секунду, `relay_cancelPrewarm()` снимает прогрев при исчезновении цели; гонг раньше `preMs` после полуночи прогрева не получает (by design донора) |
| 7 | `mp3_isPlaying()` чаще 50 мс | FIXED | состояние звука сэмплируется в `relay_loop()` не чаще `RELAY_POLL_PERIOD_MS` и кэшируется; `relay_isBusy()`/`relay_toJSON()`/LED читают кэш; `relay_stop()` обновляет его синхронно |
| 8 | Частичное применение POST `/api/relay` | FIXED | сначала валидация всех полей (тип + диапазон), затем применение; ошибка NVS → 500, а не ложный успех |
| 9 | Форма перезаписывала редактируемое поле | FIXED | dirty-флаг на `input`, сбрасывается только успешным Save; ветки enabled/disabled симметричны (поля и Save выключаются/включаются) |
| 10 | `onSince` и переполнение 2^32 | FIXED | флаг `warm` (сбрасывается при физическом OFF), а не арифметика от `onSince` |
| 11 | Тавтологичная проверка LED в тесте | FIXED | проверяется конкретный уровень в фазе, где heartbeat выключен |

Новые тесты: `deferred_fire_commits`, `deferred_fire_cancelled`,
`save_error_reported`, `legacy_import_keeps_file`, `manual_keeps_audio_hold`,
`prewarm_cancel`, `play_reports_deferral`, `busy_appears_during_hold`, LED без
тавтологии. Итог: 3110 проверок / 0 падений (relay 136, button 536,
scheduler 279, остальные без изменений).

## 10. Третий раунд ревью (26726b5)

| Замечание | Статус | Исправление |
|---|---|---|
| Apply публикует старое поколение при полуночном `sched_check` | FIXED | `courseApplyInProgress` блокирует `sched_check`/`courseAdvance`/`courseSuspend` между записью календаря и `sys_lock`-переключением |
| Ошибка перечитывания календаря маскируется | FIXED | `courseReloadCalendar()` → `bool`; при отказе Apply возвращает ошибку, расписание остаётся SUSPENDED |
| Отметка `last_fire` не привязана к запросу | FIXED | тег на каждый `relay_play()`; подтверждение только `relay_lastStartedTag()==tag`, чужой старт/замена очереди — отмена без отметки |
| Подтверждался вызов `mp3_play()`, а не старт | FIXED | `mp3_play()/mp3_start()/startNow()` возвращают `bool` (нет файла / `connecttoFS` false → не подтверждено) |
| `pending → playing`: терялись `busy` и защита реле (`hold=0`) | FIXED | `startNow()` сразу обновляет кэш аудио; реле и `busy` не «простаивают» ни один тик |
| Частичное применение NVS | FIXED | `saveConfig(mode,pre,hold)` из аргументов, RAM меняется только после успешной записи |
| Рост `pre` не сбрасывал `warm` | FIXED | при увеличении порога `warm=false`, если реле ещё не «доиграло» новый warm-up |
| Prewarm видел вчерашнее событие | FIXED | `sched_msToNext()` возвращает -1 при `courseTransitionPending` |
| Ответ Save стирал более новую правку | FIXED | dirty снимается только если поле всё ещё равно отправленному значению |

Тесты: 3131 проверка / 0 падений (relay 136+17, button 536, scheduler 283,
остальные без изменений). ASan+UBSan: relay, scheduler, button, emergency — чисто.

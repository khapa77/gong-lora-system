## Роли узлов

### Сервер (1 шт.)

- Хранит эталонное расписание и версию расписания (`schedule_version`, uint32, инкремент при каждом изменении).
- Интерфейс управления: {⚠️ Wi-Fi точка доступа + веб-интерфейс / веб-интерфейс в локальной сети / CLI по UART / дисплей+энкодер}.
  Операции: просмотр, добавление, редактирование, удаление записей расписания; включение/выключение отдельных записей; ручная команда «гонг»; просмотр статуса клиентов.
- Источник точного времени: {⚠️ NTP по Wi-Fi с записью в DS3231 / ручная установка через интерфейс}. DS3231 сервера — резерв при отсутствии сети.
- По нажатию «Sync» {⚠️ рассылает всем клиентам текущее время и актуальное расписание}.
- Может в любой момент отправить команду немедленного гонга: {⚠️ широковещательно всем / выбранному клиенту}.

### Клиент (N = {⚠️ количество} шт., адреса 1..N)

- Работает полностью автономно: связь с сервером нужна только для синхронизации.
- Хранит расписание и его версию в энергонезависимой памяти, восстанавливает при старте.
- Ведёт время по DS3231, ежесекундно сверяет текущее время с расписанием и воспроизводит звук при совпадении.
- Слушает эфир и реагирует на команды сервера.
- По нажатию «Sync» {⚠️ запрашивает у сервера время и расписание / — кнопки на клиенте нет}.
- Индикация светодиодом: норма / нет синхронизации дольше {24} ч / ошибка RTC / ошибка воспроизведения.

## Протокол обмена по LoRa

Общий заголовок вынести в `protocol.h`, используемый обеими прошивками — структуры и коды сообщений должны быть в одном месте, без дублирования.

### Формат кадра

```
magic(2) | ver(1) | type(1) | src(1) | dst(1) | seq(2) | len(1) | payload(0..N) | crc16(2)
```

- `dst = 0xFF` — широковещательный.
- `crc16` — CCITT по всему кадру до поля контрольной суммы.
- Защита от подделки команд: {⚠️ нет / усечённый HMAC-SHA256 (4 байта) на общем секретном ключе + монотонный счётчик против повторов}.

### Типы сообщений (минимальный набор, дополни при необходимости)

| Код | Имя | Направление | Назначение |
|---|---|---|---|
| 0x01 | `PING` | S→C | опрос присутствия |
| 0x02 | `STATUS` | C→S | версия расписания, время по RTC, RSSI/SNR последнего приёма, флаги ошибок, uptime |
| 0x10 | `TIME_SET` | S→C | unix-время + смещение UTC; клиент пишет в DS3231 |
| 0x20 | `SCHED_BEGIN` | S→C | версия, число записей, CRC всего расписания |
| 0x21 | `SCHED_CHUNK` | S→C | порция записей (индекс порции + данные) |
| 0x22 | `SCHED_END` | S→C | завершение передачи |
| 0x23 | `SCHED_ACK` | C→S | принято/ошибка CRC/запрос повтора порции K |
| 0x30 | `GONG_NOW` | S→C | воспроизвести звук: id звука, громкость, момент запуска |
| 0x31 | `GONG_STOP` | S→C | прервать воспроизведение |
| 0x40 | `ACK` / `NACK` | обе | подтверждение по `seq` |

### Требования к транспорту

- Полезная нагрузка одного кадра — не больше {200} байт; расписание передавать порциями с повтором только потерянных порций.
- Подтверждения и повторы: до {3} попыток, таймаут с экспоненциальной выдержкой, учитывать реальное время в эфире (ToA) для выбранных SF/BW.
- Дедупликация входящих по паре `src + seq`.
- Ответы клиентов на широковещательные запросы — со слотовой задержкой `slot = client_id * {300} мс`, чтобы не забивать эфир коллизиями.
- Параметры радио вынести в конфиг: частота, SF, BW, CR, sync word, мощность, преамбула. Значения по умолчанию: {SF9, BW125, CR4/5, syncWord 0x{12}, 17 dBm} ⚠️.
- Приём — по прерыванию DIO0 (`onReceive`), обработка — в основном цикле, не в ISR.
- Синхронность гонга: в `GONG_NOW` передавать не «играй сейчас», а «играй в unix-момент T» с запасом {2} с, чтобы все узлы зазвучали одновременно. {⚠️ нужно / не нужно}

## Формат расписания

Запись:

```c
struct ScheduleEntry {
  uint8_t  id;
  uint8_t  hour;        // 0..23
  uint8_t  minute;      // 0..59
  uint8_t  dow_mask;    // бит0 = Пн ... бит6 = Вс; 0x7F = каждый день   ⚠️
  uint8_t  sound_id;    // какой звук проигрывать                        ⚠️
  uint8_t  repeats;     // сколько раз подряд                            ⚠️
  uint8_t  volume;      // 0..100                                        ⚠️
  bool     enabled;
};
```

- Максимум {⚠️ 64} записей.
- Дополнительно: {⚠️ исключения по датам (каникулы/праздники), разовые события с полной датой} — нужно/не нужно.
- В эфире — компактное двоичное представление, в интерфейсе сервера — JSON.
- Клиент считает расписание валидным только если совпали `schedule_version` и CRC.

## Логика времени и срабатывания (клиент)

- DS3231 — единственный источник истины. Читать RTC раз в {30} с, между чтениями считать по `millis()`.
- Проверять расписание каждую секунду; срабатывание по совпадению HH:MM при `second == 0`.
- Хранить `last_fired_key` (минута последнего срабатывания), чтобы одна запись не сработала дважды в пределах минуты.
- Пропущенное срабатывание (питание пропало, узел загрузился позже): {⚠️ отыграть с опозданием, если прошло меньше N минут / пропустить молча}.
- Если новое срабатывание попадает на момент, когда звук ещё играет: {⚠️ поставить в очередь / проигнорировать}.
- Проверка живости RTC: флаг OSF (Oscillator Stop Flag), реакция на потерю питания батарейки — поднять флаг ошибки, светодиод, `STATUS` серверу.

## Аудио

- Источник звука: {⚠️ WAV в LittleFS / WAV на SD-карте / массив в PROGMEM / синтез тона}.
- Формат: {⚠️ WAV PCM 16 бит, моно, 22050 Гц}.
- Библиотека: {⚠️ ESP8266Audio (AudioGeneratorWAV + AudioOutputI2S) / arduino-audio-tools / прямая работа с I2S}.
- Воспроизведение неблокирующее: отдельная FreeRTOS-задача, приоритет ниже радио, приём LoRa во время звучания не должен теряться.
- Пин SD усилителя MAX98357A держать в низком уровне вне воспроизведения — иначе слышны щелчки и шум.
- Программная регулировка громкости; ограничение максимальной длительности звука ({⚠️ 30} с) как защита от зависания.
